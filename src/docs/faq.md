# 常见问题 FAQ

以下汇总了 VueChest 应用市场相关的高频疑问。如未覆盖你的问题，可结合 [注意事项](./market-notes.md) 进一步排查。

## Q1：上传应用失败，可能是什么原因？

上传失败通常由以下几种情况导致：

- 选择了**非 `.js` 文件** → 前端文件选择框（`accept=".js"`）会拦截。
- 文件**超过 10MB** → 前端拦截，提示"应用包不能超过 10MB"。
- 应用包**无法解析** → 提示"无法解析应用包，请确认文件是有效的市场应用"，多因未正确导出 `default.{component, route, meta}`。
- 未登录 → 上传页 `/market/upload` 需要登录态（见 [账号与登录](./account.md)）。

请对照 [如何上传应用到市场](./market-upload.md) 与 [注意事项](./market-notes.md) 逐项检查。

## Q2：为什么提示"无法解析应用包"？

这是因为你的 `.js` 包在被读取文本后，未能通过 `extractMetaFromBundle(code)` 的校验。具体原因通常是：

- 包不是由 Vite 构建的 **IIFE** 格式，或未正确暴露 `window.MarketApp`。
- 入口没有 `export default { component, route, meta }`，或三者缺一。
- 把 Vue 打进了包里（未外部化），导致加载异常。

请严格按 [应用包开发规范](./market-spec.md) 重新构建。

## Q3：审核需要多久？上传后多久能上架？

- 上传成功后应用进入**待审核**状态，**不会立即可见**。
- 审核由**管理员人工**完成，时长不固定，取决于审核队列与复杂度。
- 审核通过后应用才正式上架。若长时间未上架，可联系管理员确认（见 [审核与发布流程](./market-review.md)）。

## Q4：能不能更新已发布的应用？

可以。应用上架后如需更新，通常以**新版本**的形式重新走上传 / 审核流程：

- 在应用包的 `meta.version` 中标注新版本号。
- 重新在 `/market/upload` 提交，进入待审核 → 审核通过。
- 具体是否支持"原地更新"同一应用记录，请以平台实际功能为准；当前文档确认的上架路径为审核通过（`:id/approve`）。

## Q5：安装的应用会同步到其他设备吗？

不会。已安装列表保存在当前浏览器的 **`localStorage['market_installed_apps']`**，应用包缓存于 **IndexedDB**：

- 这是**按浏览器 / 设备**本地保存的。
- 换浏览器、清缓存或换设备后，需重新在市场里安装（见 [安装与使用](./market-install.md)）。

## Q6：安装来源不明的应用安全吗？

**存在风险。** 市场应用的 JS 在运行时从 R2 拉取并**直接注入主页面执行，无 iframe / 沙箱隔离**，与主站共享页面上下文。

- 请勿安装来源不明或不可信的应用。
- 平台正在评估改用 iframe sandbox / web worker 隔离，但当前尚未落地（见 [注意事项](./market-notes.md)）。

## Q7：应用详情页的 Markdown 说明为什么不显示格式？

当前应用详情页的 `readme` 以**纯文本**展示，**尚未渲染 Markdown**。复杂排版请在应用内或描述中说明，不要依赖详情页渲染。

## Q8：分类有哪些？可以选多个吗？

分类有 6 个：**工具 / 娱乐 / 开发 / 游戏 / 生活 / 教育**。上传时从中选择**一个**最符合的类别，不可多选。

## Q9：route 路径随便填可以吗？

不建议。路径需**全局唯一**，避免与内置路由冲突。**建议统一以 `/m/` 开头**（如 `/m/counter`）。重复路径可能导致路由覆盖或无法访问。
