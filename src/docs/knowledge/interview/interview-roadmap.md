# 前端 & Agent 面试作战手册

这套笔记面向 **中高级 Vue 3 / TypeScript 前端与 Agent 应用开发岗位**。题型参考牛客公开面经，答案用候选人第一人称组织，目标不是背概念，而是能在面试里完成「先给结论、再讲原理、最后落到工程取舍」的闭环。

### 一道题的训练方法

1. 先遮住答案，在 60 秒内口述。
2. 对照标准回答，只补自己漏掉的关键层次，不逐字背诵。
3. 回答文末的追问；追问答不出，才回专题文档补原理。
4. 用自己的项目替换示例，尤其是数据、故障与权衡。
5. 第二天、第三天和第七天各复述一次。

### 标记法

- `A`：能脱稿回答，并能接两轮追问。
- `B`：知道结论，但原理或场景不完整。
- `C`：概念混淆或只能背关键词。

复习时优先把 `C → B`，再把岗位最相关的 `B → A`。不必把所有冷门题都练到 A。

## 二、牛客公开面经反映的考察重点

近期公开面经的共同特点是：八股仍是门槛，但面试官更关心候选人能否把知识用于真实工程。

### 前端方向

高频主线可以归纳为：

1. JavaScript：闭包、`this`、事件循环、Promise、原型与手写题。
2. Vue 3：响应式、渲染更新、`ref/reactive`、生命周期、组件通信、路由与 Pinia。
3. 浏览器和网络：URL 到页面、缓存、跨域、安全、渲染性能。
4. 工程化：Vite 与 Webpack、ESM、Tree Shaking、拆包、监控和发布。
5. 项目拷打：为什么这样选、遇到什么问题、如何定位、指标怎样变化。

牛客的近期汇总把闭包与 `this` 等列为多家公司重复追问项；实际面经还会连续追问 Vue 3、事件循环、构建工具和性能优化。题型来源见[前端高频题汇总](https://www.nowcoder.com/discuss/889546972099584000)、[京东前端一面记录](https://www.nowcoder.com/discuss/comment/13344858)和[Vue 项目拷打经验](https://www.nowcoder.com/discuss/724458053038243840)。

### Agent 方向

高频主线可以归纳为：

1. Agent、Workflow 与普通 LLM 调用的边界。
2. RAG 的检索质量、更新、引用和评测。
3. Function Calling、MCP、工具路由和高风险操作保护。
4. 上下文、短长期记忆与状态持久化。
5. 单 Agent / 多 Agent 选型、通信、冲突和并发。
6. 生产工程：循环终止、幂等、重试、降级、可观测性、成本与延迟。
7. 项目证据：为什么不用固定工作流、失败样本怎样沉淀、指标是否真的改善。

近期牛客公开面经已从「会调用模型」明显转向「能交付可控系统」，常见追问包括多 Agent 编排、RAG 热更新、Agent 中断恢复、工具安全与 SSE 流式输出。题型来源见[Agent 开发面经汇总](https://www.nowcoder.com/discuss/877151327091027968)、[AI 应用开发高频 50 题](https://www.nowcoder.com/discuss/908080887516921856)和[Agent 面试题单复盘](https://www.nowcoder.com/discuss/917353328109944832)。

> 牛客用于观察真实题型和追问方式；技术结论以官方文档、规范和论文为准。不要直接背面经作者的答案，因为其中可能有版本漂移或概念误差。

## 三、标准答案的四层结构

### 原理题：结论 → 机制 → 工程 → 边界

以「Vue 3 响应式原理」为例：

1. **结论**：一句话说清楚 Proxy、依赖收集与触发更新。
2. **机制**：说明 `track/trigger`、响应式副作用和调度队列。
3. **工程**：落到 `ref/reactive`、解构丢失响应式、`shallowRef`。
4. **边界**：Proxy 只能代理对象、相等性和外部数据校验等限制。

可直接使用这个口述骨架：

> “我的理解是……。它内部主要经过三步：第一……，第二……，第三……。在项目里我会……。不过它不是在所有场景都更好，遇到……时我会改用……。”

### 对比题：共同目标 → 核心差异 → 选型条件

不要把对比题答成功能列表。比如「SSE 与 WebSocket 怎么选」：

> “两者都能做持续传输，核心差别是通信方向和协议复杂度。普通 LLM 文本流主要是服务端单向推送，我优先 SSE；如果需要客户端持续发事件、低延迟双向协作或二进制消息，我才用 WebSocket。最后还要结合代理兼容、断线恢复和团队基础设施决定。”

### 场景题：目标 → 约束 → 方案 → 失败路径 → 验证

> “我不会直接报技术名词。我会先确认数据量、时延目标、容错要求和一致性要求，再给主方案。然后补超时、重试、并发与降级，最后说明用哪些指标和实验验证。”

### 项目题：问题 → 决策 → 行动 → 证据 → 复盘

它比机械套用 STAR 更适合技术面试：

- 问题：业务痛点和可量化基线是什么？
- 决策：考虑了哪些方案，为什么这样选？
- 行动：你本人负责的关键动作是什么？
- 证据：性能、稳定性、质量或成本如何变化？
- 复盘：方案有什么边界，再做一次会怎样改？

**严禁编造指标。** 没有历史数据时可以说“当时没有完整埋点，这是复盘中最大的不足；现在我会先补基线和观测，再做优化实验”。这比虚构“提升 70%”可信。

## 四、自我介绍模板

### 90 秒前端版

> “您好，我主要做 Vue 3 和 TypeScript 前端开发，最近的工作重点是复杂交互、工程化和 AI 应用前端。项目中我不只负责页面实现，也做过状态建模、组件抽象、构建优化、错误监控和发布质量建设。一个比较有代表性的项目是【项目名】，它解决【业务问题】；我主要负责【职责】，其中最难的是【约束或故障】，最后通过【关键方案】把【真实指标】从【基线】改善到【结果】。我现在希望继续做既重视用户体验、又需要工程深度的前端或 Agent 应用开发岗位。”

### 90 秒 Agent 应用版

> “您好，我的基础技术栈是 TypeScript / Node 与 Vue 3，目前重点做 Agent 应用工程。我做过【项目名】，核心链路包括【模型接入、RAG、工具调用或工作流】。我主要负责【个人职责】，比较有价值的工作不是简单接 API，而是解决了【检索质量、工具可靠性、上下文、评测或成本】问题。我采用【关键方案】，通过【离线评测集、Trace、线上指标】验证，结果是【真实结果】。我对 Agent 的理解是，它首先是一个带不确定性的分布式软件系统，所以我特别关注权限、状态、幂等、可观测与人工接管。”

### 使用规则

- 技术栈只说与岗位相关的 3～5 个，不念技能清单。
- 项目只展开一个代表作，并埋下希望面试官追问的技术点。
- 所有“优化、提升、降低”都准备好基线、测量工具和样本范围。
- 不把团队成果全部说成个人成果，要明确“我负责”和“我们共同完成”。

## 六、面试前验收清单

### 前端

- [ ] 能在 90 秒内解释事件循环，并正确分析嵌套微任务。
- [ ] 能从 `Proxy → track → effect → trigger → scheduler` 解释 Vue 3 响应式。
- [ ] 能解释 `ref`、`reactive`、`computed`、`watch` 的边界。
- [ ] 能说明 `key` 的作用，但不会误答成“为了消除 Diff”。
- [ ] 能讲清 HTTP 缓存、CORS、XSS、CSRF 的责任边界。
- [ ] 能讲一个有真实基线、测量方法和结果的性能案例。
- [ ] 能现场写防抖、并发限制和一个数组/树转换题。

### Agent

- [ ] 能说明什么时候用 Workflow、什么时候才值得用 Agent。
- [ ] 能画出模型请求、工具调用、结果回填和终止的完整循环。
- [ ] 能解释 Function Calling 与 MCP 不在同一抽象层。
- [ ] 能把 RAG 失败拆成解析、切分、召回、重排和生成问题。
- [ ] 能分别设计检索评测、答案评测和任务级 Agent 评测。
- [ ] 能处理超时、重试、幂等、权限、提示注入和人工确认。
- [ ] 能说明上下文不等于记忆，多 Agent 不一定优于单 Agent。

### 项目

- [ ] 每个简历项目都能回答“为什么不用更简单方案”。
- [ ] 每个优化数字都有采样口径和复现实验。
- [ ] 准备一个成功案例、一个失败案例、一次线上故障复盘。
- [ ] 能明确个人贡献、团队贡献和仍未解决的问题。
- [ ] 准备 3 个对面试官有信息量的反问。

## 七、值得问面试官的问题

1. “团队当前最希望这个岗位解决的工程问题是什么？三个月后的成功标准是什么？”
2. “前端在产品、设计、后端和基础设施之间的职责边界是怎样的？”
3. “Agent 系统现在主要卡在模型能力、数据质量，还是工程可靠性？”
4. “团队如何做离线评测、线上观测和失败样本回流？”
5. “高风险工具调用有哪些权限与人工确认机制？”

避免只问官网能查到的信息。反问的目标是判断岗位真实工作、技术成熟度和成长空间。
