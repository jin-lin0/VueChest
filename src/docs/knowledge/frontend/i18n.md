# 前端国际化（i18n）

> 产品要出海/服务多语言用户，i18n 是必过的坎。本文讲清多语言方案、文案抽离与占位符、复数与懒加载，以及和暗色模式/RTL 的协作，让"加一门语言"成为低成本动作（配合 `design-token.md` 的主题体系）。

## 一、i18n 三件事

1. **文案抽离**：所有用户可见文本不放硬编码，进语言包（key → 翻译）。
2. **运行时切换**：根据用户偏好/浏览器/`navigator.language` 选语言包并响应式切换。
3. **格式化**：数字/日期/货币/复数按区域规则（Intl API）。

## 二、Vue：vue-i18n

```ts
// i18n.ts
import { createI18n } from 'vue-i18n'
export const i18n = createI18n({
  legacy: false,
  locale: 'zh-CN',
  fallbackLocale: 'en',
  messages: {
    'zh-CN': { welcome: '欢迎，{name}' },
    en: { welcome: 'Welcome, {name}' },
  },
})
```

```vue
<template>
  <p>{{ t('welcome', { name: user.name }) }}</p>
</template>
<script setup>
import { useI18n } from 'vue-i18n'
const { t } = useI18n()
</script>
```

## 三、React：react-i18next

```ts
import { useTranslation } from 'react-i18next'
const { t } = useTranslation()
return <p>{t('welcome', { name: user.name })}</p>
```

## 四、关键实践

- **占位符**：`欢迎，{name}` 避免拼接字符串，保语序（不同语言词序不同）。
- **复数**：英文 `1 item` / `2 items`；用 i18n plural 规则（CLDR），别自己 if-else。
- **数字/日期/货币**：用 `Intl.NumberFormat` / `Intl.DateTimeFormat` 而非手动格式化。
- **懒加载语言包**：按 locale 动态 `import()` 语言包，首屏只载当前语言（见 `vite.md` 分包）。
- **key 管理**：用 `i18next-scanner` 自动提取模板中的 key，减少漏翻。

## 五、与主题/RTL 协作

- **RTL（阿拉伯语等）**：`<html dir="rtl">` 翻转布局；CSS 用逻辑属性（`margin-inline-start` 而非 `margin-left`）天然适配（见 `layout.md`）。
- **暗色 + 语言**：语言和主题是独立维度，都用各自的状态/Tokens 管理（`tokens.css` 管主题，`i18n` 管语言）。

## 六、常见坑

- **文案硬编码**：开发时图快直接写中文，出海时全量返工 → 一开始就抽离。
- **拼接字符串**："{count} 条评论"在不同语言顺序不同 → 用占位符。
- **漏翻/默认回退**：缺 key 时显示 key 本身很难看 → 配 `fallbackLocale` 且监控缺失。
- **长度膨胀**：德语文案常比英长 30%，UI 留白与溢出处理要预留。

## 七、小结

- i18n = 文案抽离 + 运行时切换 + Intl 格式化。
- 占位符保语序、CLDR 管复数、懒加载降首屏。
- RTL 用 `dir` + CSS 逻辑属性；与暗色主题正交管理。
